## The shortest path

<Steps>

1. **Get your key** — put it in `DAVIRIX_KEY`.

2. **Install the SDK:**

   ```bash
   pip install davirix
   ```

3. **Send your first execution:**

   ```python
   from davirix import Davirix

   dx = Davirix(api_key=os.environ["DAVIRIX_KEY"])
   n = dx.run(agent_id="card-support", tenant_id="bank-uz",
              input={"text": "Block the card ending 7731"})

   n.status      # "completed"  — the model replied
   n.verified    # ⚡ was the ACTION confirmed
   ```

4. **Understand the difference** — `status` and `verified` are not the
   same thing. Integrating without knowing this is the most common
   mistake: [the one rule that matters](/en/boshlash/eng-muhim-qoida/).

</Steps>

## What makes it different

| | Ordinary AI pipeline | Davirix |
|---|---|---|
| Network dropped — did it happen? | ❓ doesn't know | `UNKNOWN`, retry **forbidden** |
| Retry → two SMS? | ⚠ yes | 10,000 parallel → **exactly 1** |
| Model said "I sent it" | ✅ believes it | `ACKNOWLEDGED` ≠ `VERIFIED` |
| Two years later: "why this decision?" | ❌ no trace | offline manifest, one changed byte is detected |

## The core rule

:::danger[Davirix sells the system, not the agent]
1. Business operations live **on our platform** — not in someone else's SaaS.
2. External connections serve two purposes: dealing with a **counterparty**
   (permanent) or **migrating** a customer (sunsets).
3. AI is not a separate product — it is a **feature of the system**.
4. Third parties write **domains** (inside us), not connectors (outside).
:::

⚡ That is why we do not perform work inside someone else's CRM. We run
**alongside**, show the difference, and the customer migrates when they
choose — and when they grow there is **no migration**.
